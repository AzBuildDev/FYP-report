## 1. 项目总体目标

FYP 题目方向来自：

```text
Embedded Intelligence: LLM-VLM-Powered Robot Control System
```

原始选题希望做一个轻量级 VLA / VLM 辅助机械臂控制系统，让小型机械臂可以根据视觉观测和自然语言任务执行抓取、移动、放置等操作，并最好能体现中间子目标、任务阶段理解、可解释性和泛化能力。

当前项目实际落地路线是：

1. 使用 Hugging Face LeRobot 框架控制 SO101 机械臂。
2. 使用双摄像头采集 pick-and-place 数据。
3. 使用 ACT policy 训练端到端行为克隆模型。
4. 在 ACT 推理后面增加一个轻量级 supervisory / subgoal 层：
   - ACT 负责找物体、抓取、移动到目标区、松开夹爪。
   - Supervisor 负责检测“已经在目标区松开夹爪”这个子目标是否完成。
   - 子目标完成后，自动执行一段人工示范的安全归位轨迹。

所以目前项目不是完整 openpi / π0 foundation model 路线，而是：

```text
LeRobot ACT baseline + post-release subgoal supervisor + recorded safe return-home replay
```

这个路线更适合当前 FYP 时间、硬件和 Windows 环境，因为它能在真实 SO101 机械臂上落地运行。

## 5. 为什么没有继续走 openpi / π0 主路线

之前讨论过 openpi / π0，但当前没有作为主路线，原因是：

1. openpi 官方主要面向 Linux / Ubuntu + JAX 环境，不适合当前 Windows Anaconda + LeRobot 实机调试节奏。
2. openpi 不是 LeRobot ACT checkpoint 的即插即用替代。
3. SO101 双摄、6 轴状态、夹爪范围、action normalization、policy server/client 都需要额外 adapter。
4. 训练和微调硬件要求更高，FYP 时间风险太大。
5. 当前 ACT 已经能完成抓取、移动、松开的一部分动作，继续在 ACT 上加 supervisor 更容易实机落地。

论文中可以写成：

```text
We considered using openpi / π0-style VLA foundation models. However, due to operating system support, hardware requirements, robot-specific action interface adaptation, and project time constraints, we selected LeRobot ACT as a practical baseline and implemented a post-release subgoal supervisor to improve task completion reliability.
```

### 6.5 Post-release subgoal supervisor

已完成代码修改：

```text
F:\FYP\Project\so101_mac_bringup\lerobot\src\lerobot\scripts\server\configs.py
F:\FYP\Project\so101_mac_bringup\lerobot\src\lerobot\scripts\server\robot_client.py
```

当前 supervisor 逻辑：

1. ACT 正常推理。
2. 监测 follower 的电机状态。
3. 如果满足：

```text
机械臂在目标区域附近
夹爪进入 release range
持续足够时间
```

则认为：

```text
post-release subgoal complete
```

然后：

```text
停止继续执行 ACT action queue
执行人工示范的安全归位 replay
```

当前检测参数在 `执行二十万步策略回位重放.bat` 中：

```text
post_release_home_closed_threshold=25
post_release_home_release_gripper_min=45
post_release_home_release_gripper_max=60
post_release_home_min_open_observations=10
post_release_home_release_dwell_s=3
post_release_home_min_elapsed_s=20

target pan: 35 to 65
target lift: 25 to 55
target elbow: -90 to -50
target wrist: 75 to 115
```

曾经发现并修复的关键 bug：

```text
closed_threshold=25 与 release range=45~60 冲突。
旧逻辑会先把 45~60 当作 closed，导致 release 判断永远进不去。
已经改成：closed_seen 之后，如果 gripper 在 explicit release range 内，则允许进入 release 判断。
```

## 9. 当前已知风险和注意事项

### 9.1 夹爪电机 id 6 风险

经验现象：

```text
如果夹住物体时 Ctrl+C，夹爪电机可能红灯/过载。
如果出现 id_=6 Overload error，可能需要断电重启电机/机械臂。
```

建议：

```text
尽量不要在夹爪用力夹住物体时 Ctrl+C。
如果必须停止，先让夹爪松开或让机械臂进入安全状态。
```

### 9.2 不要同时占用 COM11 / COM12

不要同时运行：

```text
robot_client
lerobot-teleoperate
record_teleop_motor_trace
```

因为它们都会占用 COM11 或 COM12。

### 9.3 当前 replay 是机械臂关节轨迹，不是视觉避障

当前归位 replay 不会实时看方块位置避障，它只是按照示范关节轨迹执行。

因此：

```text
如果物体/目标区位置变化太大，仍可能碰到方块。
如果起始姿态与 replay 第一帧差异太大，bridge 过渡仍可能不自然。
```

### 9.4 当前 supervisor 是工程增强，不是重新训练模型

不要误解为 ACT 模型已经学会完整自动归位。

更准确：

```text
ACT 模型完成抓取-移动-释放的一部分。
规则/日志驱动 supervisor 检测 release subgoal。
人工示范 replay 负责 return-home subgoal。
```
