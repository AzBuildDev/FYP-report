# 模型预热与启动检查

首次 GPU 推理可能超过动作块的有效期。实机入口现在先预热，再等待操作者按回车，之后才配置从臂扭矩并开始控制。

1. 加载模型、读取从臂状态并开启桌面相机。连接和读取阶段不发送控制目标，也不执行启用扭矩的配置；这不保证设备连接前的扭矩状态。
2. 后台对输入副本推理两次，检查每次输出为有限数值的 `[50, 6]`。第一轮允许冷启动；第二轮结果准备耗时（含线程启动、推理与结果轮询）须低于 `动作块长度 / 控制频率 − 0.25 秒`，当前预算为 **2.25 秒**。总预热最长 30 秒，失败或超时不允许开始控制。
3. 丢弃全部预热动作，重置模型队列，显示等待确认。预热中点停止或关闭监视窗口可取消，Ctrl+C 也可取消；取消不等待 GPU 完成才释放相机与串口。后台不持有机械臂对象。
4. 操作者确认后重新读取画面和关节状态。读取串口之后再次检查画面时效与停止事件，画面超过 0.5 秒即拒绝启动。控制器从新快照重新推理，预热输出不会传给调度器。

预热预算为推理留出余量，不是对后续相机、串口和 GPU 耗时的保证。等待确认可能较久，负载也可能变化；异步运行仍逐步检查相机时效、相对当前位置限幅、推理超时及动作块过期。现有功率、每步限幅 6、20 Hz 和单次 60 秒设置保留。串行对照运行中停止请求仍需等待当前推理结束。

双击 `脚本/离线实验/模型启动离线验证.bat` 可用本机基线模型和已录制画面检查预热、重新推理交接与 GPU 预热中的取消响应。它只驱动模拟关节，不打开串口或实时相机；输出独立报告到 `运行记录/模型启动离线验证_时间.json`，失败报告保留，最新成功报告另有指针。

`脚本/检查工具/控制流程完整自检.bat` 包含模型预热单元检查和真实入口的替代设备测试，检查无效输出、超预算、超时、预热取消、确认后取消/过期画面，以及正常控制的资源释放。模拟串口和相机不能证明真实硬件安全或抓取成功。

新实机日志增加 `model_warmup`，记录启动预算与各轮推理耗时，明确 `prediction_reused=false`。准备失败记录为 `preparation_end`，主动取消为 `cancelled_before_start`，都保留零动作状态；任务结果仍须操作者观察并标记。

准备阶段与位置目标发送前还会读取电机故障状态；故障或读取失败停止控制。退出时逐个尝试停扭矩并读回，保留错误并关闭串口；停扭矩未确认时仍须人工断电。监视窗口为独立 Tk 进程，退出和窗口停止通过本机文件传递，窗口异常会请求停止。2026-10-07 实机过载和修复的实际验证范围见[排查记录](项目进展/实机过载排查记录.md)，软件通过不表示硬件故障已解除。
