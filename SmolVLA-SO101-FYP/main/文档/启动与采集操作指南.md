# 启动、双摄检查与训练数据录制

适用当前中文入口和双摄版本。建议依次完成环境检查、相机检查、机械臂检查、录制保存和数据完整性检查。打开项目控制台不会启动硬件。

当前五位置实测使用最新 50 段、30,000 步实验的 best_val。旧 51 段数据的 3000 步和 10000 步模型只能大致对准物体，无法夹住并完成抓取。选择模型与对应演示的操作见 [自由选择模型与推理测试](自由选择模型与推理测试.md)，中文路径可以保留。

官方模型来源、固定下载链接、朋友训练要接收的完整批次，以及哪些文件不进 Git，见 [项目文件来源与训练交接](项目文件来源与训练交接.md)。历史 2026-10-17 批次有 51 段/27,426 帧、102 个视频，约 292 MB；它与当前五位置 50 段数据是不同批次。完整性检查通过仅表示结构与解码正常，不能据此判断演示质量。

## Python 环境与本机配置

建议复用已安装 LeRobot 0.3.4 的 Python 3.10 环境。相机和采集需要 NumPy、OpenCV、PyAV、PyArrow、Pillow、imageio-ffmpeg、pyserial、feetech-servo-sdk、PyTorch 和 LeRobot 依赖；模型训练与推理还需要兼容的 CUDA 版 PyTorch 和 Transformers。相机检查、示范录制本身不加载模型权重。

在项目根目录创建 `运行环境/本机Python路径.txt`，第一行写本机所选环境的 `python.exe` 完整路径，不加引号，保存为 UTF-8 无 BOM。该文件是纯文本，不执行配置代码。`运行环境/` 已被 Git 忽略，因此每台电脑可以独立配置；不要用 `git add -f` 强制提交该目录。

启动器依次选择：环境变量 `LEROBOT_PYTHON`、上述本机配置、项目内虚拟环境、当前 PATH。显式配置的路径失效时会报错。所有批处理沿用同一个解释器；Conda 的 DLL 和 Scripts 目录会加入本次进程 PATH，训练面板沿用自己的启动解释器，不修改全局环境或其他 Conda 环境。

双击 `脚本/项目控制台.bat`。先在“检查工具”运行“检查本地环境”，核对 Python、仓库中的 LeRobot 路径、模型文件和 CUDA 信息。软件检查会枚举串口，不连接机械臂或发送动作；软件通过不代表硬件已经准备好。没有窗口或窗口立即退出时，在 `脚本/环境配置/打开项目终端.bat` 打开的终端运行对应批处理查看错误。录制窗口错误另见 `运行记录/演示录制窗口.log`。

## 检查双摄

先关闭录制、其他预览、系统相机和会议软件，避免设备被占用。打开 `脚本/日常操作/相机测试.bat`，默认配置如下：

| 角色 | 设备名 | 方式 | 格式 | 取帧规格 | 保存规格 |
|---|---|---|---|---|---|
| 桌面 | 1080P USB Camera | 按设备名 | MJPG | 640×480，25 FPS | 640×480，20 FPS |
| 夹爪 | icspring camera | 按设备名 | YUY2 | 640×480，20 FPS | 640×480，20 FPS |

点击“开启两路”，等待错开启动。分别在镜头前移动物体，确认两路对应正确、持续更新，无黑屏或冻结；桌面覆盖方块、机械臂和目标区，夹爪能看见接近与夹持。窗口应显示“两路正在同时出画面”。预览显示限速，不能据此判断录制实际帧率。修改预览选项不会保存到正式录制；正式配置在 `脚本/程序模块/双摄采集配置.py`，更换设备需要统一修改并重新检查。

停止并关闭预览，再运行 `脚本/检查工具/双摄规格与帧率检查.bat`。默认预热 3 秒、检查 15 秒，只打开摄像头。报告保存在 `运行记录/相机规格检查_时间.json`，顶层 `passed=true` 才表示整体通过：两路尺寸正确、桌面约不低于 22.5 FPS、夹爪约不低于 19 FPS、画面年龄小于 250 ms、两路时间差小于 150 ms、无缺失配对且线程正常退出。黑帧检查是抽查，仍需人工观察画面。

失败时分别检查单路，再检查双路；排查设备占用、USB 接口、连接线、采集格式和实际支持的帧率。不要将请求帧率当作实测帧率。两台 USB 相机没有硬件曝光同步，报告使用主机收到完整帧的时间。检查结束后关闭工具，才开启录制。

## 检查主从臂

接好两臂 USB 和电源，核对标定与实际设备一致。运行 `脚本/检查工具/只读检查机械臂.bat`，确认 `BOTH_ARMS_FAULT_FREE_READ_OK: True` 和 `FOLLOWER_TORQUE_DISABLED: True`。只读检查不会写位置或配置。出现过载、读取错误或无法确认扭矩关闭时，托住从臂、断电排查，不继续启动动作。

首次使用建议先在 `脚本/日常操作/同步测试.bat` 进行短时间跟随检查，确认各关节和夹爪方向正确。该入口等待回车，正常模式默认最长 30 秒，Ctrl+C 停止；正常模式没有小行程限制，需将两臂摆成接近姿态，缓慢操作主臂。结束后确认清理无错误。

录制代码按 USB 序列号识别原有两臂，不能只改 COM 号就适配替换的控制板。更换两臂或控制板时须核对角色、序列号和标定。夹爪完整开合与负载表现仍需现场确认。

## 开始录制

1. 打开 `脚本/日常操作/录制任务演示.bat`。一个新窗口对应一个新批次。
2. 第一段选择抓取物体：RC 为红方块，BC 为蓝方块。顶部只读任务指令自动切换，与推理使用同一份规范文字。一段正常停止后程序自动在 RC/BC 间预选下一段；需要时仍可在下一段开始前手动改选。
3. 点击“开启双路相机”，确认两路持续正常出画面。
4. 将主从臂摆成接近姿态，固定目标区和相机，摆好本段物体。点击“开始一段 [F5]（最长 30 秒）”或按 F5。此操作会先启用扭矩，再倒计时 3 秒，不会再要求按回车。
5. 操作主臂完成“接近、夹取、抬起、移动、放下、松爪、撤离、归位”，动作平稳且任务完整。
6. 按 F6 或点击“停止本段”；录制窗口获得焦点且不在选择框中时也可按空格，Esc 可停止。停止会尝试释放扭矩，注意托住从臂。
7. 停止完成后，成功按 F7 保存，失败按 F8 丢弃本段并重录。正常停止时界面立即从 RC 预选 BC，或从 BC 预选 RC；F7 保存后保留该下一段选择，F8 丢弃后自动恢复刚才录制的目标。手动停止和录满 30 秒自动停止都遵循这个规则。录制中、待保存和编码时锁定物体选择，避免手动改变本段任务。快捷键只在录制窗口获得焦点时生效。

2026-10-30 起录制窗口只保留 RC/BC 物体选择，移除阶段、目的地、轮次、位置、布局及会话/操作者表单。物体选择表示本段要抓的目标，不表示场景中有几个物体；位置、单/双物体场景和配对组请另按采集清单记录。保存时每段的任务文字写入标准 `task_index`，动作备份头同时记录 `target_object_id`。自动切换只决定下一段，不会重标之前的演示；保存失败也不会切换。旧四物体标签的读取、检查和训练兼容逻辑保留，不改写已有数据。

每段最长 30 秒；少于 50 帧（2.5 秒）、相机过期、黑帧、两路时间差过大或采集明显落后的段会被拒绝保存。停止不是保存；关闭窗口会丢弃尚未保存的段。保存失败时程序保留原始文件并阻止继续录制，应保留该批次排查，不手动伪造元数据。

批次位置为项目同级的 `训练数据采集/机械臂控制项目/任务演示/双相机演示_时间戳/`。包含两路视频、Parquet 状态/动作、任务元数据和逐帧动作/时间备份。继续使用同一窗口会追加新段；重新打开会创建新批次。数据只保存在本机，不随 Git 提交上传。

## 检查保存的数据

在项目终端运行以下命令，将占位文字替换为窗口显示的本次批次完整目录：

```bat
脚本\离线实验\检查演示数据.bat --dataset-root "本次双相机演示批次的完整目录"
```

不能只双击后就默认检查了刚录的数据：入口默认路径仍指向旧历史批次。结果应为 `status=passed`、`errors=[]`，有 `observation.images.front` 和 `observation.images.wrist`，每段两路帧数与数据行数一致，尺寸、20 FPS、时间戳正确且无黑帧。报告和抽帧预览图默认保存在 `运行记录/演示数据检查.json` 与同名 JPG。检查程序不会判断物体任务成功，仍需本人观察。

先录少量完整演示并检查，再逐步采集约 50 条高质量演示。目标区固定，变化方块起始位置；保留完整演示段，最好另录独立批次用于验证。约 50 条是采集起点建议，不保证训练后成功。更换视角、安装位置或裁剪时另建批次，训练和部署保持一致。

## 训练入口与尚未解决的问题

采集训练面板已支持沿用启动解释器、读取新旧训练来源文件，并扫描 `模型/` 与 `models/`。在面板中选择刚录批次和完整段，先检查数据与训练计划，再训练新模型；默认强制留出检查会拒绝训练内容重叠。训练步数和 batch 应结合数据量与显存选择，训练不会自动替换实机入口模型。

仍需注意：

- 录制程序没有同步测试中新增的起始姿态差检查、周期电机故障检查和逐电机停扭矩读回，且录制没有单步目标限幅。不要认为其他入口的保护自动适用于录制。
- 训练和评估批处理的默认数据/模型仍有旧路径；使用面板明确选择，或显式传入 `--dataset-root`、`--model-dir`。数据检查同样需要指定新批次。
- 双击 `脚本/日常操作/启动模型推理.bat`，选择模型及对应演示后点击“启动推理”；准备通过后直接控制从臂，无需终端回车。默认勾选“持续运行，直到点击停止”；取消勾选可设正数秒（初始 30 秒）。最新五位置模型已完成五个训练位置附近的抓取与放置，仍存在中间位置泛化和放置压线问题；详见 [当前进展](项目进展/当前进展.md)。操作与检查结果见 [推理说明](自由选择模型与推理测试.md)。
- 历史每块 1 步短程配置的连续性检查未通过（4 秒 11 步、约 2.81 Hz）；新任务推理配置每块最多 10 步，保留每步限幅与故障停止。用 `模型启动离线验证.bat --task-inference` 检查新配置，报告分别保留；20 Hz 控制循环不能直接当作实际发送频率。
- 预览配置不会同步保存到正式录制。相机时间戳仅表示主机到帧时间，不能证明曝光严格同步。
- 环境安装脚本仍为 Python 3.12/CUDA 12.8 的独立安装流程，与本指南建议复用的 Python 3.10 环境不同；已有验证环境无需运行该脚本，也无需升级现有包。现有环境的部分包版本与旧依赖清单不同，通过本机检查不等于完全复现旧环境。
- 其他机器上的历史运行和数据清理记录，不代表本机已完成同样操作；原始数据、模型、标定与相机/机械臂当前状态必须分别核对。

本次软件验证（2026-10-17）：Python 3.10.20 / PyTorch 2.7.1+cu126，RTX 4060 Laptop GPU 计算通过；控制台 4 项、训练面板 19 项、训练评估数据流程 11 项检查通过。模拟双摄完整录制、停止、保存、视频重读和资源清理通过（60 帧）；本机已有 3 段、1429 帧双摄演示完整性检查通过。未打开真实相机或连接机械臂，模型离线完整启动验证的限制见上文。

## 提交代码前

正常提交共享启动器、源码和本指南；本机路径只写在被忽略的 `运行环境/本机Python路径.txt`。运行 `git check-ignore -v "运行环境/本机Python路径.txt"` 确认忽略，再查看暂存区差异。不要强制添加运行环境、本机验证报告或原始数据。LeRobot 的 `src/lerobot/datasets/` 是必需源码，应正常纳入提交，不能与原始训练数据一起忽略。
