# 训练与独立验证

划分时以完整演示段为单位，不把同一段相邻帧分到训练和验证两侧。当前流程要求两路图像、20 FPS、六个关节且动作与状态顺序一致。归一化统计与训练样本只用所选训练段，视频按需解码。新模型保存 `training_provenance.json`，包含训练段、内容指纹和检查点 SHA-256；来源读取兼容旧的 `训练数据来源.json`。

先按 [文件来源与训练交接](项目文件来源与训练交接.md) 准备官方基础模型、处理器及完整数据。以下在项目终端执行，**必须显式指定自己的数据批次**；部分入口默认路径仍是旧单摄实验。历史 51 段批次可在面板选择，段号为 0～50；该批次的 3000 步、10000 步模型实测只能大致对准物体，无法夹住并完成抓取。当前五位置成果使用另一个 50 段批次，需按其来源记录选择演示。下面用 0、1 段训练、2 段评估仅演示参数，不是正式 51 段的推荐划分；正式训练须记录所选完整段并保留独立评估数据。

```bat
脚本\离线实验\微调预训练模型.bat --dataset-root "完整双摄批次目录" --episodes 0 1 --steps 1000 --output-dir "模型\双摄留出实验_新名称" --dry-run
脚本\离线实验\微调预训练模型.bat --dataset-root "完整双摄批次目录" --episodes 0 1 --steps 1000 --output-dir "模型\双摄留出实验_新名称"
脚本\离线实验\评估微调模型.bat --dataset-root "完整双摄批次目录" --model-dir "模型\双摄留出实验_新名称" --episodes 2 --require-held-out
```

第一行只检查训练计划。训练输出目录必须为空；已有模型不会被覆盖。不指定输出目录时使用 `模型/红色方块微调_时间/`。模型在全部训练结束后保存，当前无周期检查点或断点续训。新模型不会自动替换实机入口基线。命令行训练结果默认写入 `运行记录/finetune_result_时间.json`，日志为 `finetune_log_时间.jsonl`；离线评估报告为 `模型离线评估_时间.json`，面板任务使用各自独立记录目录。

交回整个模型目录（权重、配置、统计和来源文件），同时交回训练报告/日志、段号、参数、基础模型固定版本、代码提交号和依赖版本。跨电脑加载前修正模型配置的本地处理器路径，具体见 [交接清单](项目文件来源与训练交接.md)。

评估支持 `--dataset-root "完整批次目录"`、`--model-dir`、`--episodes`、`--samples-per-episode`、`--check-only` 和 `--output-report`。`--check-only` 只检查数据与来源，不推理。`--require-held-out` 要求检查点与来源记录匹配且未发现训练内容重叠；同一批次同段号、相同动作/状态内容或相同视频都会判为重叠。复制目录或重新编号不会把相同内容变成留出数据。

现有三段、3000 步基线模型是在这次来源记录功能加入前训练的。历史训练记录确认三段均已参与训练；对这个模型重新划分三段不能产生留出验证。缺少来源文件的模型在新评估中标为 `training_provenance_unknown`，拒绝通过 `--require-held-out`。需要从基础模型用训练段重新训练实验模型。

同批次留出只检查未参与该次训练的完整段，仍可能有相同的方块位置、光照和动作习惯，不能代表新场景泛化。内容指纹可发现完整复制，不保证识别裁剪、重编码或修改过的数据；应保留原始采集批次和人工划分记录。后续优先使用另一次独立采集、不同物体位置的批次作为验证。动作误差和模型输出正常也不等于实机抓取成功。

`训练评估流程自检.bat` 使用临时软件测试素材验证划分、统计和来源绑定，不会把测试素材写入真实演示目录，也不连接硬件。
