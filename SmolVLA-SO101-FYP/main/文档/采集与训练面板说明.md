# 采集与训练面板

双击 `脚本/日常操作/采集训练面板.bat`。面板列出本项目已保存的演示批次与完整微调模型，左侧用于训练，右侧用于离线评估；两侧可以选择不同批次。

面板沿用启动它的 Python 环境，扫描 `模型/` 与早期 `models/` 目录，兼容 `training_provenance.json` 和旧 `训练数据来源.json`。环境选择见 [启动指南](启动与采集操作指南.md)，官方模型下载与朋友训练交接见 [文件来源与交接](项目文件来源与训练交接.md)。

1. 需要新演示时，点击“打开演示录制”，在独立录制窗口自行开启相机、开始一段、停止和保存。保存后回到面板刷新。采集失败批次保留并显示“未就绪”，不能启动训练。
2. 选择训练批次与完整演示段，点击“检查所选批次”，核对视频、动作、状态和时间戳。多选按 Ctrl 或 Shift；显示的第 1 段对应内部编号 0。
3. 填写训练步数、每批数量及中文实验名称，先点击“检查训练计划”。通过只表示数据和配置可用，尚未训练或保存检查点。
4. 点击“开始训练新模型”后，后台运行本地微调，窗口显示输出。模型另存到 `模型/实验名称_时间/`，保留原有基线。完成时核对报告、检查点与训练来源记录；退出码为零而没有有效报告仍判为失败。
5. 右侧选择模型和留出段或独立采集批次，先检查评估计划，再开始离线评估。默认强制留出检查，训练内容重叠或来源未知会拒绝。已有三段数据默认训练第 1、2 段，评估第 3 段；更换模型后须重新核对其训练来源。
6. “停止当前软件任务”只结束面板创建的当前软件进程，保留原始数据、日志及已有输出。中断训练不保证保存检查点，也不能自动续训；重新开始会创建新的实验目录。

每个任务使用独立的 `运行记录/采集训练面板/任务_时间/`，包含控制台输出、输入检查、结果报告和任务状态。“打开任务记录目录”打开最近任务目录。状态文件是结束时快照，不能凭旧状态认定进程仍在运行。

训练后模型出现在评估下拉列表中，实机控制仍使用原有实机基线，面板不会自动更换实机模型或启动抓取。“打开实机结果记录”用于按本人观察登记真实测试结果。关闭面板会停止自己的软件任务，独立录制窗口需自行停止和关闭。

取消“强制留出检查”可检查训练演示拟合，但不能把它称为独立验证。离线动作误差、正常输出和计划检查通过均不代表实机抓取成功率。

在项目控制台选择“采集训练面板自检”，使用临时元数据、替代进程及隐藏窗口检查流程，不训练、不连接硬件。实际批次可在面板中点击“检查训练计划”和“检查评估计划”，检查所选演示及留出约束。早期固定前三段演示的 `验证采集训练面板.py` 已完成用途并于 2026-10-19 清理。
