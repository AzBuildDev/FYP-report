# 红蓝任务语义接口与本地语音模型

语音/WAV → Whisper tiny完整转写 → Qwen2.5-1.5B-Instruct有限任务ID → 独立语义/场景校验 → 固定训练文本。
此入口仅语义预览和显式dry-run；不加载SmolVLA、不预测关节动作、不连接机械臂。

## 与红蓝30k权重一致的任务标签

| task_id | task_text（精确训练文本） |
|---|---|
| red_cube_to_zone_A | Pick up the red cube and place it in the target area. |
| blue_cube_to_zone_A | Pick up the blue cube and place it in the target area. |

显式使用 --policy-profile red_blue_30k。默认legacy_red仍只允许原红任务。
zone_A仅对应演示中的target area；yellow area是旧解析器的语言别名，不能推断支持任意黄色区域。
绿块、zone_B不在当前训练能力映射内，继续拒绝。场景过期/缺失/忙碌、对象不唯一、模型与独立语义不一致都拒绝。
Qwen原始JSON只允许status和task_id，策略配置由程序选择。

## 新电脑安装（Windows / Python 3.10）

在仓库根目录PowerShell创建自己的独立环境，不复制别人的虚拟环境：

```powershell
py -3.10 -m venv 运行环境/语音虚拟环境
$py = '.\运行环境\语音虚拟环境\Scripts\python.exe'
& $py -m pip install -r 文档/语音最小依赖.txt
# 有兼容NVIDIA GPU/驱动的本机验证组合：
& $py -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
# 没有CUDA时，改选CPU wheel，且运行命令显式加 --device cpu：
# & $py -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
& $py -m pip check
```

GPU与CPU wheel二选一。软件包安装需要访问包源和PyTorch下载站；使用适合自己GPU的驱动。
本机实测Python3.10、PyTorch2.7.1+cu128；未在全新电脑重建验收。CPU参数受支持，但1.5B完整CPU链路性能未验收。
仅运行红蓝语义适配自检.py及语音附件恢复自检.py只需Python标准库，不必安装模型或上述依赖。
本机旧重建语音环境.py是复用原环境的overlay，不是新电脑安装器。

## 获取Qwen与Whisper（任选一种）

### 本仓库Release附件

[speech-redblue-30k-20261029](https://github.com/HDTHDT/SmolVLA-SO101-FYP/releases/tag/speech-redblue-30k-20261029)
提供两个原版语音模型，仓库为私有，下载需要已有仓库读取权限；本次没有修改可见性或访问权限。
下载speech-models-manifest.json及全部speech-models-20261029.zip.partXX到同一个目录。
不能只下载GitHub自动生成的Source code.zip，也不能单独解压part01。

```powershell
& $py 脚本/程序模块/恢复语音模型附件.py --assets 'C:/path/to/downloaded-assets'
```

恢复工具先校验各分卷和完整ZIP的SHA256，再核对每个模型文件，恢复到项目模型/语音指令/。
目录已存在会拒绝覆盖；--check-only校验附件而不安装。下载约3.25GB分卷后，恢复时还需约6.51GB临时ZIP和解压空间；同盘建议至少预留12GB。
模型附件不在普通Git历史内，不包含自训SmolVLA、训练数据、虚拟环境、缓存或凭据。

## 验证和运行

```powershell
& $py -B 脚本/程序模块/红蓝语义适配自检.py
& $py -B 脚本/程序模块/语音指令自检.py
& $py -B 脚本/程序模块/语音附件恢复自检.py
& $py -B 脚本/程序模块/语音指令流程.py --text 'Put the blue cube in zone A.' --fixture-scene --policy-profile red_blue_30k --execute-dry-run
```

预期blue_cube_to_zone_A、蓝块精确训练文本、dry_run_completed、hardware_connected=false、motion_sent=false。
合成场景不是相机检测；实际外部场景用 --scene 场景.json（替换 --fixture-scene），需30秒内时间戳、明确busy=false、对象唯一与目标存在。
示例协议：{"source":"external_json_unverified","observed_at":当前UTC_Unix秒,"busy":false,"zones":["zone_A"],"objects":[{"id":"blue1","color":"blue","object":"cube"}]}。
该JSON本身也不证明真实场景，仍只供dry-run。
语音用 --audio 已有.wav 替换 --text；仅接受16kHz、单声道、PCM16、0至20秒WAV。CLI不录音，不需要麦克风/串口权限；英文默认，中文音频未验收。
CUDA不可用不会静默回退；明确 --device cpu，必要时 --timeout 300，LLM生成仍有8秒时限。

## 模型绑定及后续接口

红蓝语义配置.py仅描述项目相对checkpoint目录：模型/红蓝混合120段_20261028_均衡选色_bs64_30000/best_val。
这是本轮30k基线，SHA256为9a902835afd04a453866d346241789d8e3b6e350fcd03446ee6888739cdda310。
自训SmolVLA权重和训练数据由项目成员另行提供，本次不上传；官方smolvla_base不能代替这份红蓝任务权重。
policy_binding始终注明checkpoint_loaded=false、hardware_validated=false及待实机验证。
ready只表示通过语义软件预览，executable始终false；模型路径及哈希没有在此入口实际读取或校验。

API：compile_request(text, raw_json, scene, policy_profile='red_blue_30k')；显式DryRunExecutor('red_blue_30k').execute(request, scene)。
后续VLA适配器消费task_text、front/wrist两路RGB图像与6维关节状态，使用完整checkpoint的归一化统计。
不能直接把预览JSON传给现有实机入口。每次切换任务须丢弃旧动作并重置策略，实机控制需独立适配与验收。
