- 项目目标：SO-101 从臂根据桌面、夹爪两路图像及六关节反馈，自主抓取红色方块并放到目标区域。主线是 SmolVLA，旧 YOLO/视觉坐标映射方案不参与当前推理。

## 7. 当前控制链路与具体保护

入口：`F:/FYP/SmolVLA-SO101-FYP/脚本/日常操作/启动模型推理.bat`。

流程：选择模型/数据/处理器 → 加载 → 检查数据范围、设备身份、标定 → 开双摄并确认主窗口已显示 → 预热且丢弃预热动作 → 最终状态检查 → 当前原始位置保持 → 启用 → 闭环控制 → 停扭矩并逐个读回 → 保存退出结果。

实际输入是双摄 + 当前状态 + 固定任务文本。GPU 模型线程不读串口，控制主线程读取反馈、检查故障和发送目标；最多一份推理请求在途。新动作块到达即替换旧块，按时间跳过过期前缀，不反复回放陈旧步骤。

旧策略的问题：

```python
target = clip(model_target, current_feedback - 1, current_feedback + 1)
```

它限制了持续的跟随误差，不能等同于相邻指令限速。反馈几乎不动时，目标也一直卡在反馈附近。例如旧日志中肩反馈 −84.06、模型 −60.77，实际只发 −83.06；肘反馈 0.02、模型 −22.16，实际只发 −0.98。

当前任务策略的概念：

```python
lower = max(position_lower, previous_sent - 0.5, current_feedback - tracking_limit)
upper = min(position_upper, previous_sent + 0.5, current_feedback + tracking_limit)
target = clip(model_target, lower, upper)
```

| 项目 | 当前值 / 行为 |
|---|---|
| 控制周期 | 20 Hz |
| 相邻目标最大变化 | 0.5 归一化单位/发送步；missed tick 不应补发成大跳步 |
| 每块最多使用动作 | 10；模型仍预测 50 步 |
| 正常任务总行程 | 无额外距起点固定上限，但仍受演示与标定边界及跟随保护约束 |
| 身体运行边界 | 演示状态范围加余量，接纳当前起点，再限制在归一化标定边界 |
| 夹爪运行范围 | 演示 state/action 联集，约 7.1734～84.9701；不任意扩展到起点 |
| 跟随误差上限 | 演示全部读入段的 `P95(abs(action-state))*1.25`，裁至 2～10，夹爪再最多 3 |
| 本批上限向量 | `[4.3104,10,5.3114,4.4931,2.5834,3]`，顺序同六关节 |
| 误差突增 | 超过上限+0.05 则停止 |
| 停滞保护 | 误差达到 `max(1.5,0.8*上限)` 后，0.6 秒内没有至少 0.25 的位置进展则停止 |
| 相机时效 | 默认超过 0.5 秒、黑帧、缺帧拒绝/停止；其他准备步骤有自己的等待预算 |
| 推理超时 | 默认 3 秒；模型块有效期按 50/20=2.5 秒检查 |
| 电机故障 | 发送每步前检查，异常停止；退出逐台尝试停扭矩并确认，不掩盖失败 |
| GUI 默认时长 | 30 秒；**当前文件已允许任意有限正秒数和“持续运行直到停止”** |
| 无时限表示 | CLI `--seconds 0` → settings.seconds=None |
| 专用短测 | `--trajectory-trial` 固定 3 秒、距起点最多 8、每步 0.5 |
| 历史无参数设置的短检查 | 仍可能使用 `limited_test`、反馈限幅 1、总行程 3；不能和 GUI 任务模式混为一谈 |

跟随上限是按本批数据提出的试验参数，**不是厂家安全额定值**。尤其夹爪夹住物体后可能正常产生位置误差；当前停滞保护是否会把正常接触误当故障，需要结合画面/电流研究，不能直接删除保护。

“每次处理控制节拍”不保证每秒真的发 20 个有效动作。长时日志出现约 16.82 Hz，且 missed_ticks=0；每块最多执行 10 步、推理耗时与无新动作可发的间隔可能共同影响实际频率，尚需定量分析。

## 9. 可视化、日志与输入证据

主窗口现在同时显示双摄及六关节：实测反馈、原始模型预测、实际发送目标、限幅、最近故障码；显示推理次数、耗时、动作步数和运行时间。实测反馈为发送前采样，不表示该步发送后已经到达。

| 文件 | 作用 |
|---|---|
| `推理窗口_<时间>.log` | 子进程完整 stdout/stderr |
| `实机抓取测试_<时间>.jsonl` | 设备/模型身份、预热、边界、逐步预测/目标/反馈、退出及清理 |
| `实机抓取测试_<时间>/` | 同次输入图像目录，front/wrist JPEG与 `模型输入索引.jsonl` |
| `*_完整报告.zip` | GUI“导出日志与画面”生成的报告、JSONL及两路输入证据 |

输入证据在模型线程每秒最多保存一组，记录 `warmup`/`control`、输入 state 与原始首个动作，不是全帧视频，也不是每一个推理调用的完整轨迹。历史未启用该功能的日志无法事后补回真实图像。

典型逐步事件：

```text
action.observed_state      当前真实反馈
action.model_target        该动作步原始模型输出
action.target              经当前控制限制后的目标
action.sent_target         send_action 返回的下发指令，不等于到达位置
action.command_error       sent_target - observed_state
action.limited             model_target 与 sent_target 是否有差异
async_chunk.inference_s    本块推理耗时
async_chunk.skip_prefix    被认为已过期的前缀长度
action.chunk_index         本步采用的块内索引
end.stop_reason            time_limit / user_stop / error
end.cleanup_errors         退出清理失败信息，空数组也不代表任务成功
```

旧块级记录只有所选首个动作，不能还原每个未记录的模型目标；新格式才具有逐步 `model_target`。

## 11. 下一窗口最值得研究的问题

1. **完整失败发生在哪个阶段？** 先看最新完整日志及同目录双摄输入，人工标记接近、对齐、闭合、抬起、移动、放下各阶段，避免仅看关节动了就算成功。
2. **夹爪停滞与再次过载的关系。** 19:20日志触发夹爪跟随停滞，19:22、19:28准备日志又明确返回过载32且停扭矩未确认。当前无力反馈判据，正常物体接触也可能触发位置停滞，但不能据此将后来实际过载解释为正常抓取；需关联画面、目标/反馈、负载/电流、期间人工处置，不直接撤保护。
3. **训练与部署视觉分布是否一致？** 对照同姿态录制帧和运行帧，看 front/wrist 是否正确对应，视角/曝光/颜色、物体尺寸和起点、目标框位置、夹爪相机安装是否变化。实时画面出现过绿色背景、桌面黑框和红/粉色方块，但未完成系统图像分布分析。
4. **动作语义与起点适配。** 确认绝对归一化位置、关节顺序、夹爪新旧等价开度及MEAN_STD只处理一次；控制允许从当前姿态开始，不保证模型学过任意起始姿态。
5. **异步时序。** 定量检查约0.4～0.6秒推理延迟、跳过8～15步前缀、每块10步上限、实际16～20Hz之间的关系；别把20Hz配置当作实测20Hz，也别在没有对照前认定所有前缀跳过都是错误。
6. **相同起点的对照。** 固定相机/物体/机械起点/运行预算比较3000与10000步，保存相同诊断字段。模型采样随机性也会影响单次表现。
7. **更可靠的任务评估。** 46～50是已用于选型的验证集；需要独立录制批次或按位置/朝向定义测试集和成功率，而非只比较验证MAE或延长运行时间。
8. **训练改进是否必要。** 先排除数据/输入/控制链路差异，再讨论数据覆盖、模型步数、微调策略；目前证据不足以认定必须重训或改用其他模型。
9. **健壮性。** 缺失end日志的原因、长时停止与清理、断电后标定持久性、控制发送故障等应独立复核。当前有完整日志的停止正常，不等于所有退出路径都已实机验证。
