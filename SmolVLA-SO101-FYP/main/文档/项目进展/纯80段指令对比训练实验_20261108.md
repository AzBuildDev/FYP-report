# 纯80段指令对比训练实验

目标：改善RC/BC指令对接近动作的约束，针对改变非目标方块位置后接近动作漂移、转向错误物体的现象。用户已反馈纯80段与100段效果相近；本实验不再把20段单物体解释为主要原因。

这是基于现有流匹配损失实现的实验性辅助约束，不是SmolVLA官方保证有效的配方，也没有证明位置依赖只有一个原因。代码验收与实机效果验收分开。

## 实际改动

原有完整动作模仿和阶段采样保留。每次主更新完成反向传播后，额外从训练划分抽取8个接近窗口，RC/BC各4个；使用小批次累积梯度，避免和整个基础batch同时保留计算图。

对同一段正确示范，画面、关节状态、真实动作、流匹配噪声和时间都不变，只将红色指令换成蓝色，或反向交换。错误指令分支没有被当成新的正确标签做动作模仿。

辅助目标为：

```
L_total = L_original + weight × [mean(E_correct) + ranking_weight × mean(relu(margin - gap))]
gap = E_wrong/(1+E_wrong) - E_correct/(1+E_correct)
```

E是相同噪声、相同时间下的流匹配误差。辅助项仅统计真实的前5个机械臂关节，以及到用户标记帧为止的动作；不统计夹爪维度、填充维度和标记后的搬运归位。原损失仍然训练全部真实动作，包括夹爪、搬运和归位。

先约束正确指令的真实动作，再要求该动作在正确指令下比在错误指令下更相容。排序使用有界误差，达到间隔后不继续将错误误差推大。它不是“抓起任意物体就奖励”，不是颜色检测器，也不是对最终抓取结果的强化学习。

## 标记与适用范围

沿用原标记帧号，不改数据标签。窗口起点位于标记前，未来50帧窗口必须覆盖标记；最大范围约2.5秒。合爪前标记不被冒充为物理接触检测。

先剔除前5关节归一化运动幅度小于0.1的近静止窗口，以免把完全相同的停顿强行要求按指令分开。这只是启发式筛选，不保证窗口内每个动作都只能属于一个指令。若正负窗口实际具有共同动作，对比项可能产生错误约束，因此需要检查辅助指标与实机效果，而不是无限增大权重。

CPU数据检查发现：64个训练段中56个进入辅助对比池，16个验证段中13个进入辅助对比池。其余段未通过辅助窗口运动筛选，但仍完整参与原有模仿训练/验证，不是废片、不被删除。红蓝辅助抽样各半，留出段不参与反向传播。

## 三个独立配置

目录：`D:\FYP\AutoDL_纯80段_指令对比_20261108`

| 配置 | 原动作模仿 | 额外接近动作正监督 | 指令排序项 |
|---|---|---|---|
| baseline | 有 | 无 | 无 |
| anchor | 有 | 有 | 无 |
| contrast | 有 | 有 | 有 |

contrast与anchor的差别才是排序项本身；仅与baseline比，不能把改善全部归因于排序，因为额外接近动作正监督也变了。并不要求同时启动三轮。

候选batch沿用452、2124步、预热36步；三个配置共用相同数据划分、基础采样和学习率。主模仿窗口共960048个。contrast/anchor另有16992个配对窗口，每对含正确/错误两个指令前向；不能再声称总计算与原实验完全一样。默认辅助weight=0.1，margin=0.02，microbatch=2；均为待验证起始值，不宣称最优。

新目标显存与速度必须重新测量。启动器拒绝拿旧损失、不同源码、不同GPU或小于2GiB余量的显存报告直接开正式训练。当前候选batch不代表新目标已完成集群显存验收。

## 验证与保存

保持原动作MAE，同时在固定验证段、窗口、噪声种子上，额外报告正确指令误差、错误指令误差、间隔、正确指令误差更低的比例。该比例叫“指令相容性”，不能称作“选色成功率”。基于带噪真实动作的流匹配评分也不是自由运行的动作生成成功率。

`best_val`仍按动作MAE选取。不要仅凭新辅助指标或best_val决定成功；用独立阶段检查点检查目标固定、干扰物位置变化后的接近准确性。归一化、源码、配置、标注和数据来源随检查点保存，续训严格检查一致性；旧模型不能直接以resume混入新目标。

本地保存/加载验收发现原加载方式会把一部分保存为FP32的专家层权重先装入默认BF16参数，再转回FP32，产生不可逆舍入。新实验三个配置统一改为在加载前准备FP32训练参数。验收逐张量比较保存前后内容，再检查全精度输出和恢复后的实际更新。修复范围是新实验的训练加载流程，未改动现用实机加载器，也不能据此认定旧抓取失败就是精度问题。

## 入口

项目总控制台 → 离线实验 → 检查八十段指令对比实验。

这个入口只核验文件、测试采样并显示计划。GPU小批实现验收使用项目的`脚本/程序模块/验收指令对比反向传播.py`，仅临时更新副本和保存恢复，不连接实机。

在独立实验根目录内，使用已安装项目依赖的解释器执行：

```
python 启动指令对比训练.py --arm contrast
python 启动指令对比训练.py --arm contrast --benchmark
python 启动指令对比训练.py --arm contrast --run --stop-after 16
python 启动指令对比训练.py --arm contrast --run --resume
```

第一行仅显示计划。后三行分别是4次临时显存测试更新、正式16步保存检查、从完整last严格恢复。正式运行需要支持BF16的集群GPU，检查依赖和可用显存后执行；不要在另一个占满GPU的训练上并行启动。

当前改动未上传集群、未启动新一轮正式训练，也没有停止旧训练。保存/恢复小批验收仅证明代码路径可执行，不能证明新方法提高实机准确率。
