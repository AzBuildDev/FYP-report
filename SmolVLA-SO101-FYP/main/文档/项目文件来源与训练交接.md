### 标定为什么需要保留

当前机械臂标定文件是：

```text
标定备份/robots/so101_follower/my_awesome_follower_arm.json
标定备份/teleoperators/so101_leader/my_awesome_leader_arm.json
```

它们保存关节零位/偏移与行程范围，决定原始电机读数如何换成 LeRobot 归一化位置：身体关节约 -100～100、夹爪 0～100，单位不是角度。当前采集程序明确使用此标定目录，并检查两臂标定。文件较旧不等于无效；本机 10 月 17 日保存的只读电机快照与上述文件偏移和范围一致，但这不能证明现场机械安装、夹爪负载和设备故障已经正常。

这些电机关节标定与已淘汰 YOLO 路线的桌面视觉映射是两回事。单纯换项目名称或电脑盘符不需要重新标定。换电机、重装关节或改变零位/行程时须重新核对；重标定也可能改变数据中的坐标定义，不能无记录地把前后数据混合。

本次 51 段批次中没有自动冻结的关节标定副本。建议把采集时使用的 `标定备份/` 另外备份，附上批次名、日期、两臂身份与安装变化说明。朋友做离线训练无需这些硬件文件；朋友若用另一套机械臂部署，不能直接覆盖自己的标定。

## 朋友收到后如何训练和交回

1. 拉取本项目 main，记录提交号，在自己的 Python 环境安装仓库中的 LeRobot 0.3.4 与兼容依赖。当前本机验证版本见 [本地部署说明](本地部署说明.md)。官方软件来源：[Python](https://www.python.org/downloads/)、[Anaconda](https://www.anaconda.com/download)、[PyTorch](https://pytorch.org/get-started/locally/)、[LeRobot 上游](https://github.com/huggingface/lerobot)。Anaconda 可选；不要直接套用最新版 LeRobot v3 数据格式命令到本批 v2.1 数据。
2. 将数据完整解压，下载固定版基础模型与处理器；Windows 按 [启动指南](启动与采集操作指南.md) 配置自己的解释器。朋友若用 Linux，批处理和 Windows 相机入口不能直接使用；可在项目根目录设置 `PYTHONPATH` 指向 `上游框架/src`，用相同 Python 模块离线训练。本次没有验证朋友的 Linux/CUDA 环境。
3. 在“采集与训练面板”选择本批 51 段，先检查数据与训练计划；按完整段划分训练/验证，记录段号。命令示例见 [训练与独立验证流程](训练与独立验证流程.md)。这次 51 条可作首轮实验，不保证足够覆盖随机位置和方块旋转；优先另录独立验证批次，再根据真实失败区域补采。
4. 先短训练确认显存、保存和加载，正式训练输出到新目录。当前训练脚本仅在完整训练结束时保存，没有周期检查点和断点续训，长训练中断可能没有可用输出。训练不需要连接相机或机械臂，也不需要你的本机 Python 路径。
5. 交回**整个新模型输出目录**，至少包含 `model.safetensors`、`config.json`、`dataset_stats.json`、`training_provenance.json`。同时交回对应 `finetune_result_*.json`（面板任务中的结果报告名称可能不同）、`finetune_log_*.jsonl`、训练/验证段号、参数与实际依赖版本。当前来源文件未单独记录基础模型 revision，因此还要保留本表固定版本和代码提交号。
6. 跨电脑使用时在 [模型选择窗口](自由选择模型与推理测试.md) 选择检查点、对应演示和本机处理器。模型配置中的训练机器路径可以保留，启动与离线评估的加载器只在内存中覆盖处理器路径，不必改训练原文件。数据来源文件里的旧数据绝对路径用于追溯，保留内容指纹，不要为了改路径删改训练段或检查点指纹。

仅传回一个 `.safetensors` 文件不够。新模型须在启动窗口中明确选择；部署检查和安全验证还需单独完成。2026-10-18 朋友交回的模型包已解压至本项目 `模型/双摄模型_3000步与10000步/`，包含两个检查点、配套处理器和实验记录；均不随 Git 分发。
