# 2026-11-02 系统内存停滞修复

凌晨日志最后记录8700步，最后完整检查点8000步。进程仍在，但RSS约58GiB，达到实例memory.high（约58GiB）后持续发生内存回收，GPU利用率为0；未见cgroup OOM kill。停止旧进程后内存释放。

已确认的直接问题是系统内存压力导致停滞。隔离视频读取试验中，GC未释放额外对象，malloc_trim释放约698MiB空闲原生内存，说明分配器保留了部分内存；这尚不足以将全部58GiB增长归因于某一个库。

修复保持训练模块源码、输入、随机采样、模型、batch32、损失、优化器和学习率不变：

- 子进程使用MALLOC_ARENA_MAX=2，MALLOC_MMAP_THRESHOLD_=131072，MALLOC_TRIM_THRESHOLD_=131072。
- 内存稳定运行.py在AdamW每50次更新后执行GC和malloc_trim，并记录前后RSS。
- 更新后RSS超过32GiB时请求PAUSE，原训练器完成验证、保存完整last并退出；后台内存稳定训练.py随后移除内部标记并恢复。
- 进程组总RSS超过48GiB或15分钟没有指标更新时，后台调度结束该组并从最后完整检查点恢复，异常恢复连续最多3次。此应急路径可能重做尚未保存的更新。
- 用户主动PAUSE会保持停止，不触发自动续训。

CPU等价检查：100次AdamW更新后，原版与维护包装层的参数、优化器状态、学习率调度状态完全相同，Torch随机状态未变化。服务器以原检查点的严格配置指纹校验恢复，不放宽恢复检查。

原8K文件以硬链接保留在故障备份/20261102_内存停滞/第8000步，权重SHA256与来源记录一致；原metrics和配置同时归档。8700步之后没有完整保存，不宣称恢复了这些未保存的更新。
