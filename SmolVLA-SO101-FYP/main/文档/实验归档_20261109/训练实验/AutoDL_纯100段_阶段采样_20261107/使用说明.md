# 纯100段阶段采样训练包（2026-11-07）

仅使用刚标注的 `双相机演示_20261030_200119_173830` 100段，红蓝各50；没有混入之前200段。数据和标注均另存到独立训练包，原文件保持不变。

本机文件夹：`D:\FYP\AutoDL_纯100段_阶段采样_20261107`。

## 怎样训练

每次输入一帧双摄图像、该帧关节状态和对应RC/BC英文任务，目标仍是从该帧起完整50步的真实动作。标记之后的动作不会截断；搬运、放置、归位继续通过全段采样学习。标注字段沿用导出的first_contact和原帧号，准备过程不重新解释或改动帧号。

默认B实验：batch32，其中标记前抓红8、标记前抓蓝8、全段抓红8、全段抓蓝8。全段池也可能抽到标记前，因此实际标记前输入比例可以超过50%。A实验为原全段采样，红16蓝16。两者的候选训练预算均为30K更新、warmup500、峰值1e-4降至2.5e-6，每1K验证、每5K独立保存。不是在旧模型上额外训练30K。

从官方SmolVLA基础模型开始，两者各自新建优化器，不继承旧模型/旧优化器。A/B唯一预设差别是采样，分别输出到 `输出/A_纯100段_full`、`输出/B_纯100段_stage`。

80段训练（红40蓝40）、20段验证（红10蓝10），保持完整演示段划分；统计只用训练段。不声称布局独立验证，因为尚未逐组核实布局配对。验证会记录全段和标记前输入的动作误差，仍不能把它们当作选色准确率。

阶段采样是待验证的实验设置，不是已证实的颜色选择修复。没有新增反指令损失，也没有把错误动作当示范。只有后续实机对照才能判断选色和抓放是否改善。

## 上传到AutoDL后

以下是后续实际训练的操作说明。本次准备没有执行带`--run`的命令，也没有远程启动训练。

1. 把完整ZIP上传到实例 `/root/autodl-tmp`，解压。建议先核对ZIP旁的SHA256。不要与旧200段训练包合并目录。
2. 若该实例已有上一轮相同环境，可复用其Python环境；新实例可在训练包内执行 `bash 安装依赖.sh`。参考环境是支持BF16的单卡4090D 24GB；本机2080Ti不支持本入口要求的BF16。
3. 进入训练包，激活对应环境后，执行数据与标注核验：

```bash
cd /root/autodl-tmp/AutoDL_纯100段_阶段采样_20261107
source .venv/bin/activate
python 准备训练.py
```

此命令检查全包清单及已完成的完整解码记录，重新绑定本机数据路径，并验证标注及采样。它不启动训练。若希望重新逐帧解码，使用 `python 准备训练.py --full-decode`。

4. 先只看计划：

```bash
python 启动训练.py --arm B
```

5. 确定正式启动时执行：

```bash
screen -S smolvla100B
python 启动训练.py --arm B --run
```

按Ctrl+A、D离开screen而保持训练。A对照使用 `--arm A --run`，在B结束后单独运行，避免同卡并发争抢显存。两者不是一次命令自动都跑。

6. 需要暂停时，在对应输出目录建立PAUSE文件。程序完成本步及验证保存后退出；不要在保存过程中直接关实例。确认需要恢复时先移除该PAUSE，再执行：

```bash
python 启动训练.py --arm B --run --resume
```

恢复绑定标注、源码、官方权重、数据划分、学习率和优化器状态；不允许把旧200段或旧纯100段检查点混入本实验。暂停/训练配置变更不能伪装成严格恢复。

## 验收边界

准备包含数据/视频完整解码、标注视频SHA256、来源隔离、采样范围、红蓝比例、完整动作窗口、CPU真实批次对齐及抽样恢复一致性检查。未加载GPU模型、未执行优化器更新；4090D上的实际显存、前向反向与完整保存恢复仍待实际启用前验收。

训练结果首先比较相同摆放下RC/BC的选色、夹起和放置成功率，覆盖颜色换位和不同点位。`best_val`仍按动作误差选取，不能直接称为选色最好的检查点。
